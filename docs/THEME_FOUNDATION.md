# Canonical theme foundation

src/styles/themes.css is now the canonical runtime token definition imported by globals.css; Tailwind 4 @theme inline continues to map shadcn semantic names. Existing palette values are preserved, avoiding an unreviewed visual redesign. src/styles/blog.css defines prose/media behavior against those tokens.

Use data-theme-scope="public|blog|admin|terminal" to identify the surface and data-theme="light|dark" to select an explicit local variant. Root retains the legacy light baseline and .dark class compatibility. Public/blog/admin/terminal layouts explicitly default dark to preserve the existing design; public body has its own scope without replacing the homepage. Nested explicit variants reset the complete semantic palette; terminal keeps prompt green and mono identity. Publishing forms and their media panel now use semantic colors and are exercised in both variants. Other existing hardcoded colors and Tailwind dark ancestor variants still require incremental migration; scopes are a token contract, not a claim that every legacy component supports every combination.

Both palettes include background/foreground, card/popover, primary/secondary/muted/accent, destructive, border/input/ring, charts/sidebar and radius. Never duplicate these definitions in component files. Use semantic classes and scope-local overrides. Dark/light prose screenshots exercise actual tokens, including caption contrast.

Future admin customization should expose a versioned typed model: scope enum, mode enum, a small approved palette/font/radius preset and bounded numeric values. Validate on server and client, enforce admin permission and fresh revision, preview in an isolated subtree, require explicit publish and retain rollback history. Do not accept raw CSS, JavaScript, HTML, external font URLs, arbitrary Tailwind class strings or url() values from settings. Store draft separately from public configuration and serialize public tokens only. Verify contrast/focus/forced-colors for every preset before publishing. Theme persistence/schema/editor UI is not implemented in this phase.
